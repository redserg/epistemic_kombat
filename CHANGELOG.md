# Changelog

Этот файл ведётся в прикладном формате: не только "что изменилось", но и "какую проблему или фичу это реализует".

## Unreleased

### `59f35b8` Add local and cloud LLM modes

Проблема / фича:
Проект был жёстко привязан к облачному OpenAI-compatible endpoint через `NEBIUS_*` переменные. Это делало локальный запуск через Ollama неочевидным и неудобным, а переключение между локальной и облачной моделью требовало ручных правок в конфиге и знания внутренних деталей кода.

Что изменено:
- Добавлен отдельный конфиг режимов LLM в `config/llm_modes.yaml`.
- Появился модуль `llm_config.py`, который резолвит режим запуска, endpoint, ключ и model alias для ролей `judge` и `boss`.
- В проект введены два готовых режима:
  - `cloud`: Token Factory / Nebius с `openai/gpt-oss-20b`
  - `local`: Ollama с `gpt-oss:20b`
- `main.py` переведён на нейтральный слой конфигурации вместо прямого чтения `NEBIUS_API_KEY` и `NEBIUS_BASE_URL`.
- Сохранена обратная совместимость со старыми `NEBIUS_*` переменными.
- Добавлены `.env.example` и обновлён `.env`, чтобы режимы были видны и готовы "из коробки".
- Добавлены тесты `tests/test_llm_config.py`.

Эффект:
- Переключение между локальным и облачным запуском теперь делается одной переменной: `LLM_MODE=local` или `LLM_MODE=cloud`.
- Подключение Ollama стало штатным сценарием, а не неявным хаком.
- Конфигурация провайдера стала расширяемой: позже можно будет добавить новые режимы без переписывания `main.py`.

### `6b77a8e` Add localized multi-stage debate campaigns

Проблема / фича:
Игра была по сути прототипом одного боя: один босс, одна тема, одна языковая версия. Пользовательский запрос требовал большего масштаба: двуязычность, несколько тематических треков и развитие спора по уровням.

Что изменено:
- Добавлен новый модуль `game_content.py` для загрузки и рендера контента кампаний.
- Добавлен большой конфиг `config/campaigns.yaml` с локализованными кампаниями.
- Игра теперь поддерживает:
  - два языка: `ru` и `en`
  - два трека: `earth_shape` и `light_nature`
  - несколько последовательных уровней внутри каждого трека
- Для трека о форме Земли добавлены следующие уровни:
  - плоская Земля
  - геоцентризм / движение Земли
  - космология и история Вселенной
- Для трека о природе света добавлены уровни:
  - экстрамиссия и природа зрения
  - природа цвета
  - эфир и распространение света
- Появились локализованные prompt-шаблоны:
  - `prompts/boss_prompt.ru.txt`
  - `prompts/boss_prompt.en.txt`
  - `prompts/judge_prompt.ru.txt`
  - `prompts/judge_prompt.en.txt`
- `GameState` расширен метаданными кампании, языка и текущего уровня.
- `main.py` переработан так, чтобы выбирать кампанию, продолжать сохранённую игру и автоматически переводить игрока на следующий этап после победы.
- Добавлены тесты `tests/test_game_content.py`.

Эффект:
- Игра перестала быть одноразовым сценарием и стала небольшим контентным движком.
- Новый контент теперь можно добавлять в конфиг без большого вмешательства в код.
- Двуязычный режим стал полноценной частью игры, а не внешним дубликатом файлов.

### `00be466` Make boss replies resilient to blank output

Проблема / фича:
В логах уже были случаи, когда босс возвращал пустой ответ или обрывался на полуслове. Для игрока это выглядело как сломанная сцена, даже если API фактически что-то попыталось вернуть.

Что изменено:
- Добавлена очистка ответа босса перед показом пользователю.
- При пустом или явно плохом ответе добавлена повторная попытка генерации.
- Для босса введён более компактный лимит на длину ответа, чтобы уменьшить вероятность обрезания.
- Добавлен внятный fallback-ответ, если обе попытки не дали пригодного текста.
- Написаны тесты на helper-функции очистки и локализации сообщений.

Эффект:
- Игрок реже сталкивается с пустыми репликами.
- Даже при сбое модельного ответа игра остаётся разговорно целой и не разваливается визуально.

### `8c16cc3` Harden judge JSON responses

Проблема / фича:
Судья регулярно возвращал слишком длинный или битый JSON, из-за чего игра падала в `Fallback: judge error`, а боевая логика начинала деградировать.

Что изменено:
- Для judge-ответов введён более жёсткий лимит `max_tokens`.
- На повторной попытке судье даётся дополнительная инструкция вернуть только короткий JSON.
- Добавлен helper для извлечения JSON-объекта из текста, даже если модель обернула его лишним мусором.
- Расширены тесты для проверки JSON helper-логики.

Эффект:
- Судья стал заметно устойчивее к частично испорченным ответам.
- Ошибки сериализации и обрезки теперь чаще исправляются автоматически, без перехода в деградированный режим.

### `f577448` Trim boss history to prevent prompt bloat

Проблема / фича:
История диалога передавалась боссу целиком. По логам было видно, что prompt быстро разрастался, токены дорожали, а ответы чаще обрезались по `finish_reason=length`.

Что изменено:
- Введено окно истории для босса.
- Теперь сохраняется стартовая реплика и только ограниченный хвост последних сообщений.
- Добавлен тест на поведение окна истории.

Эффект:
- Снижена стоимость и длина boss prompt.
- Уменьшен риск обрезания ответа.
- Поведение стало стабильнее на длинных матчах.

### `860f2e8` Persist the next turn number immediately

Проблема / фича:
После полного хода игра сначала сохраняла state, а номер следующего хода увеличивала только потом в памяти. Если процесс прерывался между этими действиями, игрок мог вернуться в неконсистентное состояние с повтором номера хода.

Что изменено:
- Инкремент хода вынесен в отдельный helper.
- Порядок операций изменён так, чтобы после полноценного обмена репликами сохранялся уже следующий номер хода.
- Добавлен regression test.

Эффект:
- Продолжение игры стало консистентнее.
- Снизился риск странного UX после прерванной сессии.

### `b47bf30` Preserve unfinished games on quit

Проблема / фича:
Команда выхода `quit` вела себя как завершение игры: матч архивировался и текущий state удалялся. Это ломало нормальный сценарий "выйти сейчас и продолжить позже".

Что изменено:
- Введено явное определение terminal outcome.
- Архивация и очистка current state теперь происходят только для реально завершённых матчей.
- Для незавершённой игры состояние сохраняется как пауза.
- Добавлен regression test.

Эффект:
- Игру теперь можно безопасно прервать и продолжить позже.
- История больше не смешивает незавершённые сессии с настоящими завершёнными матчами.
